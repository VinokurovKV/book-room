# BookRoom

Данный проект представляет собой небольшое веб-приложение для бронирования переговорных комнат, например, при работе в разных городах и/или офисах. Написан в рамках отбора на стажировку во frontend-разработку в Avito летом-осенью 2026.

В приложении можно выбирать офисы, смотреть доступные переговорки, просматривать расписания по конкретным комнатам, создавать и отменять бронирования, например, для дейликов или планирований своей команды.

## Технологии

- React (`19.1.0`)
- TypeScript (`5.9.0`)
- Vite (`7.1.0`)
- React Router (`7.8.0`)
- Material UI (`7.3.0`)
- Vitest (`4.1.11`)
- Testing Library (`16.3.3`)

Backend используется из задания. Он хранит данные, проверяет ограничения бронирований и отправляет real-time события через WebSocket.

## Запуск проекта

Для запуска проекта необходим Node.js 20 или выше.

### 1. Установить зависимости backend

```bash
cd server
npm install
```

### 2. Запустить backend

```bash
npm run dev
```

### 3. Установить зависимости frontend

В новом терминале:

```bash
cd frontend
npm install
```

### 4. Запустить frontend

```bash
npm run dev
```

Далее можно открыть клиентскую часть по ссылке:

```text
http://localhost:5173
```

## Маршруты

- `/rooms` - список переговорных
- `/rooms/:roomId` - страница переговорной и расписание
- `/bookings` - мои бронирования
- `/` - редирект на `/rooms`
- неизвестный адрес показывает страницу "Ничего не найдено"

## Что реализовано

Ниже находится выжимка из ТЗ и README серверной части по заданию с добавлением того, что было реализовано в проекте. Основная цель - собрать рабочий пользовательский сценарий: от выбора офиса и поиска переговорной до создания бронирования, обработки конфликтов и управления своими бронями. Старался соответствовать предложенным макетам из папки images, но, разумеется, не слишком точь-в-точь.

- выбор офиса перед просмотром переговорных;
- фильтры списка комнат по дате, времени, длительности и вместимости;
- отображение доступности переговорных на выбранный интервал;
- страница комнаты с расписанием на день;
- форма создания бронирования;
- валидация формы бронирования;
- обработка конфликта бронирования;
- страница успешного бронирования;
- список моих бронирований;
- фильтры бронирований по офису и дате;
- разделение предстоящих и прошедших бронирований;
- отмена будущих бронирований;
- loading, error и empty состояния;
- real-time обновление броней через WebSocket.

## Real-time

Клиент подключается к WebSocket backend API и слушает события создания и отмены бронирований.

Благодаря этому без перезагрузки страницы обновляются:

- доступность комнат в списке переговорных;
- расписание открытой переговорной.

## Принятые решения

- Для коммитов использовал привычный себе единый и понятный стиль: `"feat/fix(frontend/backend)"`, потому что так привычнее и улучшает читаемость репозитория.
- Для интерфейса решил использовать библиотеку Material UI, потому что с ней уже достаточно много работал, компоненты уже стали привычными и удобными.
- В backend добавил метод `DELETE`. По условиям задания не было ничего сказано про запрет изменений сервера, поэтому посчитал, что добавление одного метода не должно стать проблемой. Благодаря ему получилось самое логичное на мой вгляд решение для отмены бронирования.
- В задании не было указано необходимое количество написанных unit-тестов, поэтому посчитал, что около 50 штук должно быть достаточно разумным количеством.
- По календарю: в спеках даты в прошлое тоже выглядят активными, но в подписи под самим календарём написано, что учитывать только будущие даты на 30 дней вперёд, поэтому сделал даты в прошлом неактивными, кроме страницы "Мои бронирования", чтобы там можно было смотреть все прошедшие, что по-моему логично.
- Не очень понял по макету с деталкой комнаты, какие именно события должны быть бирюзовыми в цвет темы, поэтому сделал таким цветом те события, которые по заданию изначально лежат на сервере.
